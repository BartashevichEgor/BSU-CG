# Защита ЛР №2: обработка изображений

## Демонстрация за 3–4 минуты

1. Загрузить `02_low_contrast_gray`; показать Y-гистограмму. Сравнить «Линейное контрастирование» и «Эквализация».
2. Загрузить `03_outliers_gray`; объяснить, что пиксели 0 и 255 уже задают min/max, поэтому растяжение почти ничего не меняет.
3. Загрузить `01_color_low_contrast`; эквализировать сначала RGB, затем HSV: только V. Показать, что RGB меняет оттенки, V сохраняет H и S.
4. На `04_dark_underexposed` включить логарифм или γ=0,5; на `05_bright_overexposed` — γ=2.
5. На `06_uniform_gray` применить растяжение и эквализацию: результат остаётся 128, потому что обработаны граничные случаи.

## Где находится каждая часть

- `imageMath.js` — только формулы и проходы по пикселям.
- `histogram.js` — подсчёт 256 уровней и рисование двух графиков с общим максимумом.
- `testGenerator.js` — шесть детерминированных ImageData, не нужны внешние файлы.
- `app.js` — выбирает метод, но всегда передаёт ему `source`, а не предыдущий `result`.

## Алгоритмы

### Поэлементная операция

```text
для каждого пикселя и каждого канала R,G,B:
  вычислить g по выбранной формуле
  записать clip(round(g), 0, 255)
alpha не изменять
```

Формулы: `f+c`, `f*k`, `255-f`, `c*ln(1+f)`, `255*(f/255)^gamma`. Для логарифма автоматический `c=255/ln(1+max_f)`.

### Линейное контрастирование

```text
найти min и max выбранной величины i
if min == max: вернуть исходник
для каждого i: T(i) = round(255 * (i-min)/(max-min))
```

В `gray` величина — Y=round(0.299R+0.587G+0.114B), результат серый. В `rgb` три диапазона и три независимые формулы. В `hsv` величина — V=max(R,G,B): RGB→HSV, заменить V, HSV→RGB; H и S не менять.

### Эквализация

```text
h[0..255] = 0
для каждого пикселя: h[i]++
if занят только один уровень: вернуть исходник
C = 0
для i=0..255:
  C += h[i]
  T[i] = round(255 * C / N)
для каждого пикселя: заменить i на T[i]
```

Для RGB строятся три массива `T`; для HSV(V) — один массив по V. При V=0 остаётся чёрный, чтобы не получить ошибочное преобразование оттенка.

### Гистограмма

```text
для каждого пикселя выбрать Y, R, G, B или V
увеличить bins[value]
sharedMax = max(max(binsBefore), max(binsAfter))
рисовать каждый столбец с высотой bins[i] / sharedMax
```

## Ответы на типовые вопросы

**Почему результат не накапливается?** В `processFromOriginal()` каждый метод получает неизменяемый `source`. Иначе после нескольких действий нельзя честно сравнить методы, и накопится округление.

**Почему эквализация не всегда «улучшает» картинку?** Она выравнивает распределение уровней, а не распознаёт объекты; может усилить шум и изменить естественный контраст.

**Почему выбросы вредят растяжению?** Формула смотрит только на min и max. Одного 0 и одного 255 достаточно, чтобы диапазон стал полным.

**Почему RGB-эквализация меняет цвет?** Для одного пикселя R, G и B проходят через разные таблицы T; их отношение меняется. При обработке V H и S сохраняются.

**Почему `min == max` и одноуровневую гистограмму надо обрабатывать отдельно?** В первом случае в знаменателе 0; во втором таблица по формуле искусственно отправила бы единственный уровень в 255, что не является корректным сохранением однотонного изображения.
