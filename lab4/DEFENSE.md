# Что показать на защите ЛР №4

1. Откройте вкладку «Часть 1». Покажите входной формат, систему координат, оранжевое окно, серые исходные и зелёные видимые отрезки.
2. Выберите отрезок, который пересекает окно. Объясните: сначала строятся коды концов; при `OR = 0` отрезок принимается, при `AND ≠ 0` отбрасывается. В остальных случаях внешняя точка заменяется пересечением с границей. В таблице это видно по каждой итерации.
3. На примере `(-7,-2) — (7,3)` и окна `[-4,-3] — [4,3]`: для первой точки код `0001`, для второй — `0010`; первая замена — пересечение с `x=xmin`, вторая — с `x=xmax`; результат `(-4; -0.929) — (4; 1.929)`.
4. Выберите отрезок `(-6,4) — (-2,6)`. У обеих точек есть общий бит `T`, следовательно `code0 & code1 ≠ 0` и он целиком невидим. Это тривиальное отклонение без вычисления пересечений.
5. Перейдите к части 2. Объясните, что окно — выпуклый отсекатель, поэтому многоугольник последовательно отсекается четырьмя его полуплоскостями: слева, справа, снизу, сверху. В таблице после каждой границы дан новый список вершин.

## Короткие ответы

**Почему код четырёхбитный?** Каждая граница прямоугольного окна отвечает за один независимый признак: левее, правее, ниже, выше.

**Почему общий внешний бит гарантирует невидимость?** Если обе точки находятся по одну сторону одной границы, весь соединяющий их отрезок находится в той же внешней полуплоскости.

**Почему нельзя всегда принять `OR ≠ 0`?** Концы могут быть с разных сторон окна; такой отрезок может пересекать его, поэтому нужен расчёт пересечения.

**Чем различаются алгоритмы?** Сазерленд—Коэн обрабатывает один отрезок и использует коды областей. Сазерленд—Ходжмен обрабатывает список рёбер многоугольника, формируя новый список вершин после каждой границы.

**Сложность.** Для одного отрезка Сазерленд—Коэн выполняет конечное (не более нескольких) число пересечений; для `n` отрезков — `O(n)`. Сазерленд—Ходжмен при четырёх границах обрабатывает каждый получившийся список вершин, то есть линейно по числу вершин для фиксированного прямоугольного окна.
